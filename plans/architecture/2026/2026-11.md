## ADR-0008 — Product inception ends at an epic queue filed in Plane

- **Status:** Accepted
- **Date:** 2026-11-26
- **Domain:** Planning and specs
- **Confidence:** High — Joseph, 2026-11-26, plan decisions D3 and D5
- **Supersedes:** ADR-0006
- **Superseded by:** None

### Context

ADR-0006 handed each epic to an OpenSpec change for buhhdy's Workflow 1, promoted
decisions with `promote-adr.ts`, and dispatched the phases through buhhdy's
Workflow 0. The cleanup pass is removing buhhdy, OpenSpec and `promote-adr.ts` from
huhhb. Joseph chose to keep product-inception standing alone, so the skill must end
at outputs that need none of those systems: epics filed as work items in the repo's
Plane project, and decisions recorded in the repo's own decision log.

### Options considered

| Option | For | Against |
|--------|-----|---------|
| A. File each epic in Plane with `plane-work-tracking`; record decisions with `repo-memory` (chosen) | Epics become work items someone can pick up; decisions land in the repo's existing decision log | Needs a Plane project in the repo |
| B. Keep the Epic Queue only in `prd.md`; file nothing | No tracker dependency | Epics are invisible to the tracker |
| C. Retire product-inception | No skill to maintain | Rejected by Joseph; the skill is kept |
| D. Do nothing | No change now | The skill would point at skills and scripts the cleanup pass removes |

### Decision

Product inception ends at the Epic Queue in the PRD. On architecture approval, each
epic is filed as a Plane work item in the repo's Plane project, in dependency order,
using the `plane-work-tracking` skill: as an Epic work-item type where the project
has one, with each `depends-on` becoming a blocked-by relation. Filing dispatches
and starts nothing. Each `AD-N` block in `architecture.md` is recorded as one
architecture decision with the `repo-memory` skill, one record per decision. A repo
with no Plane project presents the Epic Queue as the hand-off instead of filing it.

Four decisions from ADR-0006 carry forward, one of them with a changed condition. ADR-0006 decision 1 stands: product-inception is its own skill, entered only on an explicit request and never inferred from task size. The rejection of BMAD's story and sprint layer in ADR-0006 decision 2 stands. ADR-0006 decision 3 stands: the artifacts live at `plans/product/<initiative-slug>/{brief,prd,architecture}.md`, a repo without the layout keeps one `docs/plans/product-<slug>.md` instead, and `repo-kickstart` is suggested once and never mandated. Its condition changes: the layout applies when `plans/architecture/DECISIONS.md` exists, in place of the OpenSpec conformance probe. ADR-0006 decision 7 stands: the template structure is adapted from BMad Method v6.x, attributed in the skill's `reference.md`, and nothing is vendored. ADR-0006 decisions 2 (where inception ends), 4 (how decisions are recorded, now by `repo-memory` in place of `promote-adr.ts`), 5 (the Epic Queue lived in `prd.md` only; it is now written in `prd.md` and filed in Plane) and 6 (dispatch of each phase through Workflow 0) are replaced by this record.

**Tradeoff accepted:** the tracked hand-off needs a Plane project in the repo.
Per-phase dispatch and the opposite-vendor cross-review after each phase are gone.
`promote-adr.ts`'s per-slug idempotency is gone, and repo-memory does not check for
an existing record of the same decision, so a re-run can record the same decision
twice.

### Consequences

- **Positive:** Each epic is a Plane work item someone can pick up, with its
  blocked-by relations. Decisions are recorded in the repo's decision log, owned by
  repo-memory. The skill no longer names skills or scripts that the cleanup pass
  removes.
- **Negative:** Without a Plane project the Epic Queue stays a presented hand-off
  only. Per-phase dispatch and cross-review are gone. `promote-adr.ts`'s per-slug
  idempotency is gone.
- **Follow-on work:** None in this record. Deletion of buhhdy and OpenSpec is
  tracked separately.
